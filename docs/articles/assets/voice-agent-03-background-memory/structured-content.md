# 结构与核对项

## 图 1：前后台如何协作

- 用户向前台提出要求，前台回应或播报。
- 前台向协调层委托或修改请求；协调层维护请求 ID、要求版本，以及独立的执行与播报状态。
- 协调层向后台传入任务输入；后台回传进度或结果；协调层向前台提供有效状态。
- 后台调用业务工具并接收真实回执。
- 执行期间前台继续接收输入；打断音频与取消业务分别处理。

## 图 2：记忆如何进入前后台

- 用户原话与已交付内容形成对话历史，近期原文与较早摘要分别保留。
- 要求变化与工具回执更新请求状态，覆盖版本、进度和交付。
- 业务资料与用户偏好分别保存，图中归为同一来源组；组内仍是不同记录。
- 应用从历史选取前台语境，并为后台建立任务快照。
- 应用把请求进度与结果组装到前台上下文；后台按需读取业务资料与偏好。
- 两边使用独立上下文；保存期限和持久化取决于各类数据用途。

图 2 只突出创建快照、读取状态与按需取资料。执行中的修改入口、摘要版本核对、Realtime 连接更新由正文展开。
