# Fast path / Slow path 配图结构

依据：第三篇“意图判断分布在三个位置”“一项请求怎样在两条路径之间推进”“记忆分别保存，按用途进入上下文”。
布局：structural-breakdown；风格：craft-handmade；语言：中文；画幅：4:3；后端：内置 imagegen。

## 图 1：职责与协作

- Fast path：接话、轻量路由、读取状态、表达结果。
- 请求协调：维护请求 ID、要求版本、执行状态与播报状态；校验路由与过期结果。
- Slow path：业务理解、执行计划、独立工作上下文，调用工具并接收回执。
- 连接：用户输入和回应；快路径委托或控制及协调层回传；协调层传快照与后续修改，慢路径回传进度与结果；慢路径调用工具及工具返回回执。
- 只表达逻辑职责；协调层可以实现在运行时中，图不表示进程或模型数量。

## 图 2：按更新时机同步记忆

1. 受理：原话和相关历史经选择形成含身份、范围和版本的快照，传入慢路径。
2. 执行：慢路径的工具回执更新请求状态，快路径读取有效进度和结果。
3. 交付：播放流程记录结果引用与交付情况到历史，应用为下一轮选取上下文。

资料与偏好按需读取；历史压缩异步完成，校验版本后替换旧片段。两条路径各自保留工作上下文。此图为应用设计示意，不暗示全部记录持久化，也不代表 Mina 已具备长期偏好。
