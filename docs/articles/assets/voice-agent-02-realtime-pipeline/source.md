# 本次结构图使用的事实

摘自配图前文章及已核对的实现：

- 客户端音频经 RTC 到达应用，应用做音频适配、唤醒和准入，再经 WebSocket 输入 Qwen。
- 应用控制响应；模型生成音频或返回工具调用请求。
- 应用校验参数、权限与轮次有效性，调用业务服务，按 call_id 回传结果。
- Qwen 回传结果后还需 response.create 续答。
- 查询错误、拒绝执行或超时也要有对应结果；拒绝执行时不调用业务服务。
- response.audio.delta 交付到应用，再进入输出与播放链路。
- 停止发声不等于完成表达。
- 第二轮“谁参加”依赖第一轮选中的会议。
